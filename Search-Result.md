# Search Result — Field Explanation

Sample search result from Azure AI Search index `rp-foundry-rag` with semantic reranking enabled.

---

## Scoring Fields

| Field | Value | Explanation |
|---|---|---|
| `@search.score` | `0.0252` | **BM25 relevance score** — the base text-matching score from the initial retrieval stage. This is a raw relevance score based on term frequency and inverse document frequency. Lower values indicate weaker keyword overlap with the query. |
| `@search.rerankerScore` | `2.9237` | **Semantic reranker score** (0.0–4.0) — a deep learning model (from Bing) re-evaluates the top results for semantic relevance, not just keyword matching. A score of ~2.9 out of 4.0 indicates strong semantic relevance. This is the score you should sort/filter by when semantic ranking is enabled. |

> **Key insight:** A document can have a low BM25 score (weak keyword match) but a high reranker score (strong semantic match). This is exactly why semantic reranking matters — it catches results that are conceptually relevant even when they don't share exact keywords with the query.

## Semantic Captions

```json
"@search.captions": [
  {
    "text": "We routinely assess our high-risk suppliers' conformance to industry standards...",
    "highlights": "We routinely assess our<em> high-risk suppliers' conformance </em>to industry standards..."
  }
]
```

| Field | Explanation |
|---|---|
| `text` | **Extractive summary** — the semantic ranker identifies the most relevant passage (~200 words) from the chunk and returns it as a caption. This is useful for displaying snippets to users or feeding directly to the Distiller agent. |
| `highlights` | **Same passage with highlight markers** — `<em>` tags wrap the most relevant phrases within the caption. Useful for UI display to draw attention to key terms. |

> **Pipeline impact:** Semantic captions can optionally replace or augment the Distiller agent's job — the ranker has already identified the most relevant passage, so the Distiller has less work to do.

## Document Identity Fields

| Field | Value | Explanation |
|---|---|---|
| `chunk_id` | `f1cfecd9fec4_..._pages_121` | **Unique chunk identifier** — auto-generated by the Import Data wizard. The suffix `pages_121` indicates this is page 121 of the source PDF. The prefix is a hash of the parent document. |
| `parent_id` | `aHR0cHM6Ly9zdGZvd...` | **Base64-encoded source document URL** — identifies the original blob (`https://stfoundryrag.blob.core.windows.net/rag-documents/www-sec-gov-nvda-20260125.pdf`). All chunks from the same PDF share this parent_id. |
| `title` | `www-sec-gov-nvda-20260125.pdf` | **Source file name** — the blob name from which this chunk was extracted. Useful for citations in the RAG pipeline. |

## Content Field

| Field | Explanation |
|---|---|
| `chunk` | **The actual text content** of this chunk. The Import Data wizard splits the PDF into chunks (default: 2000 characters with 500-character overlap) and stores each chunk as a separate document in the index. This chunk covers NVIDIA's cybersecurity governance, supplier risk assessment, and board oversight — from their 10-K filing. |

## Vector Field (not shown in results)

| Field | Explanation |
|---|---|
| `text_vector` | **1536-dimensional embedding** generated by `text-embedding-3-small` during indexing. Not returned in search results by default (too large), but used internally for vector similarity search. When a query is vectorized, Azure AI Search computes cosine similarity against these vectors to find semantically similar chunks. |

## How These Fields Map to the RAG Pipeline

```
User Query
    │
    ├── Vector Search (uses text_vector) ──→ @search.score (BM25 component)
    │                                   ──→ @search.rerankerScore (semantic)
    │
    ├── Semantic Captions ──→ Distiller input (pre-extracted relevant passages)
    │
    ├── chunk ──→ Full context for the LLM
    │
    └── title + parent_id ──→ Citation source for the Synthesis agent
```
